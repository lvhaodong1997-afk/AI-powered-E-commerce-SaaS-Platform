# 双桶发布实施计划

用户已批准本方案并要求：同步最新代码，完成开发，推送，部署服务器。

## 全局约束

- 素材库原文件和后续素材上传留在 tk-material-factory，不批量迁移或改素材 URL。
- 新生成最终视频及必要发布附件、发布页上传视频/图片、开放 API 发布文件写入 tk-video-create。
- 发布经 https://tkpublish.fnn.net.cn 使用 PULL_FROM_URL，配置或访问失败时给明确错误。
- 历史文件按需复制为发布副本；原文件不动，同源版本可复用。
- 对象真实位置随记录/会话固定；签名、校验、删除、清理不得因当前默认桶变化而跨桶操作。
- 保持租户/公司/API 客户端权限校验、已有接口及执行中 publish_id 幂等行为。
- 不提交或部署原工作区的无关改动；部署保留线上其它功能，备份并准备回滚。

## Task 1：后端双桶与发布文件准备

改动产品根 yudao-module-tk/ 内配置、upload、tiktok、open/tiktok、相关清理服务与聚焦测试，必要时新增 SQL 增量脚本。

1. 新增独立发布 OSS 配置，默认禁用以兼容原部署；启用后必须完整校验，不能悄悄退回素材桶。
2. 复用 OSS 传输实现，按用途/真实 URL 选择配置；素材默认客户端不改目的桶。
3. 调整生成输出、后台视频/图片全部上传方式、开放 API 上传的 policy、上传、完成校验、取消、清理；上传会话绑定原目的地。
4. 增加发布文件准备服务及轻量映射表，依据来源真实 bucket/key 与版本建立发布副本，限定受信来源和已校验所属范围，禁止任意 URL/SSRF；同地域 OSS copy，小文件直接复制、大文件采用 multipart copy，失败可重试，最终 URL 不带读取签名。
5. 接入后台和开放 API 的视频/图文发布，已存在 publish_id 不重复初始化，旧成片/素材按需准备副本。
6. 长耗时复制必须在现有异步发布执行阶段，避免请求线程等待触发524；不在数据库长事务中进行复制。
7. 针对分桶路由、历史读签名、复制复用/错误/权限边界、完成与清理、直拉及任务幂等先写失败测试，再实现并运行聚焦测试。

## Task 2：前端与配置文档

复用发布中心交互，保留上传选择，展示现有任务阶段或明确的文件准备失败信息。若现有异步任务状态已覆盖准备阶段，则不新增多余接口或前端状态。补充双桶配置示例、SQL路径、生命周期及回滚说明，禁止提交秘密。

## Task 3：独立审查与验证

审查后端与前端变更，覆盖来源授权、URL解析、同key跨桶、旧任务、并发复制、API兼容及生命周期。修正重要问题后运行TK相关测试、编译打包；有前端变更则运行对应测试和类型检查/构建。

## Task 4：推送与部署

1. 再同步远端，提交仅本任务文件并推送 codex/dual-bucket-publish。
2. 重新读取线上版本/配置/任务，保存配置、DB增量前状态和原发布版本；仅新增本功能SQL和配置，旧素材记录不更新。
3. 修正 tk-video-create 发布目录匿名 Get 和 CNAME 访问；禁止匿名写，素材权限调整须保证原授权读路径兼容。
4. 构建可审查发布产物；若线上有本分支未包含的其它功能，保留原jar其它entry，仅合并本次变更及实际新增依赖，并逐项核验。
5. 准备完整新release，校验后切换，重启 tk-yudao-prod；启动失败自动切回原release和配置。
6. 验证服务健康、域名真实匿名GET/Range、写入目标桶、素材原文件可读和部署hash；不真实发帖，报告此验收边界。
