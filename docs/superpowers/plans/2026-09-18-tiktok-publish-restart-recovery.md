# TikTok 发布重启恢复实施计划

**目标：** 仅修改 A 方，使发布任务在服务重启后可以恢复并补发已有回调，C 方保持现有接口和事件不变。

**方案：** 以数据库中的发布详情为恢复依据；已有 `publish_id` 的任务继续调用 TikTok 状态接口；终态记录缺少回调事件时补建原有事件；没有 `publish_id` 的中断任务保持处理中并禁止自动重发，避免重复发布。

**范围：** 后端 TK 开放 API、回调事件幂等、数据库升级 SQL、单元测试。C 方接口和回调契约不变。

## 任务

1. 先补充恢复和回调补偿的失败测试，验证重启场景。
2. 修改发布恢复任务，恢复已有 `publish_id` 的记录，并把未知发布保留为处理中。
3. 为发布回调增加 A 方内部去重键，终态事件缺失时重新入队。
4. 增加幂等数据库升级 SQL，并完成 TK 模块测试。
5. 构建、提交、推送，并按部署文档同步服务器和验证线上进程。
