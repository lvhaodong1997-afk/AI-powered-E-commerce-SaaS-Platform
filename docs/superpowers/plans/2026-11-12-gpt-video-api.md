# GPT 自动出片 API 实施计划

**目标：** 使用已有账号登录及刷新令牌，独立 API 完成积分、素材库、音色、自有 BGM 查询、手动口播生成、进度及成片下载地址获取。

**边界：** 不改前端、既有接口默认行为、TikTok 开放签名 API、生产系统或数据库结构。采用 `/admin-api/tk/automation/v1` 和现有 JWT/租户/权限体系。现有 Open API 客户端不含租户账号绑定，不能用它替代用户身份。

1. 新增资源/任务 DTO、Controller 和服务，调用既有业务服务。为参数映射、自有 BGM、失败返回、下载权限和 HTTP 契约先写测试。
2. 补齐上次开始的 `/tk/bgm/user-list`，仅返回当前账号上传且可读的曲目，测试排除同租户他人的上传。
3. 新增可选 `durationMode=FOLLOW_NARRATION`，快照到现有任务 route config。未设置时保持网页现有行为；API 必须探测配音长度，规划取整但最终渲染使用精确配音时长，超限明确失败。
4. 生成参数只接收口播正文、音色和 BGM 等明确字段；固定中国大陆、无翻译、1080x1920/30fps，默认开启特大白字黑边/智能避让/关键词/逐字字幕，混音 v2 的 0.4 音量。
5. 新增调用文档和请求示例，说明人群音色/BGM池、刷新令牌、错误码及下载过期后重新查询。
6. 运行 TK 模块依赖构建及上述测试、既有生成/字幕/混音/权限测试，检查聚焦 diff。无需部署；真实账号素材与完整媒体出片需在可用测试环境联调。

**P1/P2：** 幂等任务提交、回调通知、标签选画面作为后续扩展，本次不伪装为已支持。调用方创建任务后不得在响应不明时盲目重试。
