# TikTok Shop P0 联调与审核

## 当前代码边界

前端使用 `/admin-api/tk/tiktok-shop`，实际部署前须确认反向代理将该前缀转发至后台。OAuth 回调为 `/admin-api/tk/tiktok-shop/auth/callback`，服务端生成回调页面并向已配置的 HTTPS 前端 origin 发送一次性窗口消息。前端只接受 `event.origin === capabilities.callbackOrigin`、来源窗口等于同步打开的 popup、消息类型 `tiktok-shop-auth` 且 sessionId 完全一致的消息。

前端不保存 app secret、access token、refresh token，不把 token 放入 URL 或 localStorage。反向代理和应用访问日志不得记录 callback 的 code/state 查询串，日志示例应只包含路径和状态：

```text
POST /admin-api/tk/tiktok-shop/auth/callback 200 request_id=redacted
```

回调地址必须与平台登记值逐字一致（HTTPS、域名、路径）。服务端环境变量使用 `TIKTOK_SHOP_ENABLED`、`TIKTOK_SHOP_APP_KEY`、`TIKTOK_SHOP_APP_SECRET`、`TIKTOK_SHOP_REDIRECT_URI`、`TIKTOK_SHOP_FRONTEND_ORIGIN`、`TIKTOK_SHOP_TOKEN_ENCRYPTION_KEY`、`TIKTOK_SHOP_SELECTION_PROOF_KEY`、`TIKTOK_SHOP_MEDIA_ROOT`、`TIKTOK_SHOP_WORKERS`、`TIKTOK_SHOP_MARKET=US`。secret 只通过服务端环境注入；不要把真实值写进前端、样例、录屏或提交。`TOKEN_ENCRYPTION_KEY` 与 `SELECTION_PROOF_KEY` 使用独立随机 Base64 32-byte key，并按既有密钥管理流程保存，禁止复用 app secret。

## 权限、数据库和运行条件

先应用 `yudao-module-tk/src/main/resources/sql/tk_tiktok_shop_publish_mysql.sql`，再启用服务。角色至少需要父菜单 `tk:video-publish-center:query` 和对应 Shop 子权限：账号 query/authorize、publish query/create/confirm。只给 Shop 访问时不需要普通 TikTok mutation 权限；生成视频选择另外需要 `tk:generation:query`，上传路径只需要 Shop publish:create。数据库迁移和角色授权须由管理员在目标环境执行并留存 SQL 审核记录。

所有 worker 必须挂载同一个受信任、不可被外部写入或公开列目录的 `TIKTOK_SHOP_MEDIA_ROOT`。媒体快照由后台解析、校验和锁定，前端确认页只展示 source ID、文件大小、文件名/商品 ID 等安全元数据，不把可变源 URL 当成锁定快照预览。发布配置缺失时允许连接账号，但商品和任务创建必须禁用。

## P0 录屏步骤

1. 使用具备父菜单和 Shop 子权限的 US creator 测试角色进入发布中心，切换 TikTok Shop；确认能力配置和账号状态显示，不出现伪造的已连接成功。
2. 点击“连接官方创作者账号”。窗口必须先同步打开，再跳转到平台；完成 `creator.video.write` 授权并返回精确登记的回调地址。回调成功后刷新账号列表，以服务端账号列表作为连接依据。
3. 选择一个真实生成成功的视频，或通过上传路径选择一个 MP4/MOV/WEBM 视频；观察上传进度、取消和完成后的 mediaId。录屏应显示视频 source ID/大小等锁定元数据。
4. 选择商品来源 SHOP 或 SHOWCASE，选择真实可售商品并保留服务端 selectionProof；切换账号、来源或过滤条件后旧商品和分页结果必须清空。
5. 填写不超过 2200 UTF-16 单元的视频文案、少于 30 codepoints 且无标点/emoji 的商品链接标题，确认 AI 标识。创建任务只执行上传/预检，不直接发布。
6. 查看服务端预检。违规 FAIL 必须阻止确认；quality FAIL 仅作 advisory，并在确认页逐条显示 code/risk/suggestions 文本。
7. 打开锁定任务确认页，核对账号、source ID、fileSize、商品 ID/link title、caption、AI flag、version、requestHash 和预检问题。勾选“我确认以上是要发布的锁定任务快照”后只提交一次 confirm。
8. 观察 CREATED/UPLOADING/PRECHECKING/AWAITING_CONFIRMATION/SUBMITTING/PROCESSING/SUCCESS 等阶段。PROCESSING 不得显示成功；RECOVERY_REQUIRED 只提示人工核验和 requestId，不提供自动重试按钮。成功且官方安全返回 videoId 时才显示公开视频链接，否则只显示 ID。
9. 刷新页面，打开任务历史中的 AWAITING_CONFIRMATION 或终态任务，确认详情来自服务端不可变任务快照，当前编辑草稿不会替换历史详情。

## 外部审核门槛

上线前仍需平台官方权限审核或 beta 准入（如要求）、合格 US creator、平台注册的精确 redirect URI、服务端 app secret 和密钥配置，以及 provider verification。当前本地行为测试、类型检查和后端 synthetic tests 都不能证明真实授权、商品目录、预检或公开发布成功。必须在获批测试账号上完成一次端到端 pilot，并人工核对 TikTok 的最终视频状态；不得把代码测试结果写成已成功发布。
